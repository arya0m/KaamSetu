## What Phase 1 built

- **Monorepo** laid out per PRD. This folder is the repo root; there is no nested `kaamsetu/`.
- **`docker-compose.yml`:** `postgres` (`pgvector/pgvector:pg16`), `redis` (7, append-only persistence), a one-shot `migrate` service, `api` and `worker`.
  - **Shared image:** `migrate`, `api` and `worker` all run the image built from `apps/api/Dockerfile` (Python 3.12).
  - **Migrations:** `migrate` runs `alembic upgrade head` once, and `api`/`worker` wait for it to complete successfully. Never move migrations back into the api command, or several replicas would race.
  - **Hardening:** app containers run with `init: true`, a read-only root filesystem (tmpfs `/tmp`) and `no-new-privileges`, as non-root uid 10001.
  - **Ports:** host ports bind to 127.0.0.1 only.
- **`apps/api/Dockerfile`:** multi-stage. Dependencies install from `requirements.lock` with `--require-hashes --only-binary=:all:` into `/opt/venv`, and the runtime stage copies only that venv and the code. Uvicorn is PID 1 (exec form), so SIGTERM triggers graceful shutdown, and runs with `--proxy-headers` (trusting `FORWARDED_ALLOW_IPS`), `--no-server-header` and `--timeout-graceful-shutdown 20`.
- **Lock files:** `apps/api/requirements.lock` (runtime) and `requirements-dev.lock` (runtime + dev) are hash-pinned and generated by `uv pip compile` from `pyproject.toml`. **After changing dependencies in `pyproject.toml`, regenerate both** (command under "How to run").
- **`app/config.py`:** pydantic-settings, environment only. `DATABASE_URL` and `REDIS_URL` have no defaults. Holds the match weights, threshold and max distance (validated to sum to 1), `EMBEDDING_DIM`, and DB pool and connect-timeout settings. **With `APP_ENV=production` the app refuses to start** if any connection URL still contains `change-me` or `DASHBOARD_ORIGIN` isn't `https://`. A test fails if any setting is missing from `.env.example`.
- **`app/main.py`:** `create_app()` factory. OpenAPI at `/api/v1/openapi.json`, docs at `/api/v1/docs`. CORS allows only `DASHBOARD_ORIGIN`.
- **`app/errors.py`:** every error uses `{"error": {"code", "message"}}`. Raise `AppError(code, message, status)` from app code. Unhandled exceptions return a generic 500.
- **`app/readiness.py` and `routers/health.py`:**
  - `/healthz` is pure liveness.
  - `/readyz` runs registered checks concurrently under one shared deadline (`READINESS_TIMEOUT_S`). It returns 200, or 503 with `checks` listed. Failure details go to logs only.
  - Phase 1 registers `database`, `pgvector` and `redis`. **Later phases must register their providers** (STT, LLM, embeddings), e.g. `app.state.readiness.register("llm", check_fn)`.
- **`app/models/`:** all 10 PRD tables. Every table gets UUID `id`, `created_at` and `updated_at` from `TimestampedBase`. Native PG enums for trade, job status, application status and message direction. The `vector(EMBEDDING_DIM)` columns are on `worker_profiles` and `jobs`.
- **`migrations/versions/0001_initial.py`:** handwritten, mirroring the models. It creates the `vector` extension and reads `EMBEDDING_DIM` from settings. `test_p1_migration_matches_models` fails on any drift, so write a new migration whenever you change a model.
- **`app/workers/`:** Celery app on Redis (JSON only, acks late, prefetch 1) and a `kaamsetu.ping` task.
- **`.github/workflows/ci.yml`:**
  - `lint`: ruff check, ruff format check, `mypy app tests`.
  - `audit`: `pip-audit --strict` on the runtime lock.
  - `test`: pytest against Postgres+pgvector and Redis service containers, gated at 80% coverage or more.
  - `compose`: the Phase 1 done-when, in CI. It runs `docker compose up --build`, checks `/readyz` is green and a Celery ping round-trips, and asserts the API stops in under 10 s (graceful shutdown).
  - Installs come from the hash-pinned dev lock, and the workflow has read-only `contents` permission.
- **`.pre-commit-config.yaml`:** ruff, ruff-format, mypy, private-key detection.
- **Empty packages:** `schemas/`, `services/`, `ai/`, `i18n/`, `apps/dashboard/` and `seed/` are placeholders for later phases.

### Data-model decisions made in Phase 1 (confirm or change)

- `worker_profiles.worker_id` is UNIQUE, which is how "one active profile per worker" is enforced.
- `applications` is UNIQUE on (worker_id, job_id), like `matches`.
- `messages.worker_id` and `messages.wa_message_id` are nullable. The first allows pre-consent and unknown senders; the second is NULL on outbound messages until WhatsApp returns an ID. Postgres UNIQUE still allows multiple NULLs.
- `audit_log` has no foreign keys, so entries survive a worker's deletion (FR-11).
- Worker child rows use `ON DELETE CASCADE`, so a hard delete of `workers` removes profile, voice notes, matches, applications and messages.
- `workers.state` is a free `String(32)` with no default. Phase 2 defines the states.
- `jobs` CHECK constraints: `pay_min <= pay_max`, `openings >= 1`.

### Gaps for later phases (PRD is silent, so ask before adding)

- **FR-14:** the job form has **shifts**, but `jobs` has no shifts column.
- **Match score (Phase 5):** experience fit needs the job's **minimum years**, but `jobs` has no such column.
- **FR-17:** "median time to first interest" may need an interest timestamp. `applications.created_at` might be enough.

## What Phase 2 built (WhatsApp loop, FR-1)

### Decisions that deviate from PRD.md (made with the user, 2026-10-13)

- **Provider:** the Twilio WhatsApp sandbox, not Meta's Cloud API. This changes the PRD's webhook spec:
  - **Signature:** requests are signed with `X-Twilio-Signature` (HMAC-SHA1 over the public URL plus the sorted form parameters), not `X-Hub-Signature-256`.
  - **No GET handshake:** `GET /webhooks/whatsapp` returns 405.
  - **Delivery statuses** arrive on `POST /webhooks/whatsapp/status`.
  - **Swappable:** the provider sits behind `WhatsAppProvider`, so a Meta provider can be added later.
- **Numbered menus, not buttons:** the sandbox can't send custom templates, so it can't send quick-reply buttons ([Twilio sandbox docs](https://www.twilio.com/docs/whatsapp/sandbox)). Workers reply with a number, which can be in their own script's digits ("१", "৩"), or with a word ("हाँ", "yes", a language name). Buttons can come back once there's a registered WhatsApp sender.
- **13 languages instead of 3:** Hindi, English, Bengali, Marathi, Telugu, Tamil, Gujarati, Kannada, Malayalam, Odia, Punjabi, Assamese and Urdu. **A native speaker should review the translations** before the demo; they live in `app/i18n/locales/*.json`.
- **Pre-consent state lives in Redis only:** the step and chosen language are stored under `onboard:<phone hash>` with `PRECONSENT_TTL_S` (24 h). Nothing touches Postgres until "I agree"; declining deletes the key.
- **Phone numbers stored as plaintext until Phase 7**, per the user's choice. `wa_phone_hash` is HMAC-SHA256 with the secret `PHONE_HASH_SALT`; never change the salt once workers exist. `wa_phone_encrypted` holds the plaintext via `PlaintextPhoneCodec`. **Production refuses to start** while `PHONE_ENCRYPTION=none`.

### Code

- **`app/routers/webhooks.py`:** checks the body size, parses the form, verifies the signature against `PUBLIC_BASE_URL` + path, claims the message ID in Redis, queues the work and returns empty TwiML.
  - **Malformed but signed requests** get a 200 and are dropped, so Twilio doesn't retry garbage.
  - **Queueing failures** get a 503 and release the claim, so Twilio's retry goes through.
- **`app/services/whatsapp.py`:** the `WhatsAppProvider` protocol, `TwilioProvider` (httpx; classifies errors as transient or permanent and never logs phone numbers or text) and `SendThrottle`, which spaces sends via Redis to respect the sandbox's 1 message per 3 s (`WHATSAPP_MIN_SEND_INTERVAL_MS`).
- **`app/services/conversation.py`:** a pure state machine: new → awaiting_language → awaiting_consent → active (echo). Each inbound message produces exactly one reply, which suits the sandbox's rate limit.
- **`app/services/inbound.py`:** applies an outcome to Redis and Postgres.
  - **On consent** it creates the worker (with `consent_at`), writes an `audit_log` entry and starts logging messages.
  - **Duplicates** are caught twice: the Redis claim, then `messages.wa_message_id` UNIQUE with `ON CONFLICT DO NOTHING`.
  - **Concurrent "yes" messages** create only one worker.
- **`app/workers/tasks.py`:**
  - `handle_inbound` computes the reply and queues `send_text`.
  - `send_text` sends with retries: 3 attempts, exponential backoff with jitter.
  - `update_message_status` applies delivery-status callbacks.
- **`app/i18n/`:** `t()`, the bilingual welcome (Hindi and English, privacy link, numbered menu of all 13 languages, under 300 characters), and language and consent matching.
- **Tests (`test_fr1_*` / `test_p2_*`):**
  - **Coverage:** i18n completeness and 300-character limits for every key in every language, every state-machine transition, the Twilio signature cross-checked against Twilio's official SDK, exact send payloads, and retry classification.
  - **Webhook behaviour:** the throttle, rejecting bad signatures, de-duplication, and the 503 that releases the claim.
  - **Full DB flows in Hindi and English:** declining stores zero rows, the TTL is set, duplicates are suppressed after consent, concurrent consent creates one worker, the status callback updates the row, and sending succeeds on the 3rd attempt or gives up after 3.
  - **Guard:** a test fails if non-ASCII (worker-facing) text appears in app code outside `app/i18n`.

### Connecting the Twilio sandbox (the remaining done-when)

1. **Join the sandbox:** in the Twilio Console, go to Messaging → Try it out → Send a WhatsApp message, and join from each test phone by sending the shown `join <code>` message.
2. **Expose the API publicly over HTTPS:** for example `cloudflared tunnel --url http://localhost:8000` or `ngrok http 8000`.
3. **Fill in `.env`:** set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `PUBLIC_BASE_URL=<tunnel URL>` and `WHATSAPP_MIN_SEND_INTERVAL_MS=3000`, then run `docker compose up -d`.
4. **Set the webhook:** under Sandbox settings, set "When a message comes in" to `<tunnel URL>/webhooks/whatsapp` (POST). It must match `PUBLIC_BASE_URL` exactly, or every signature check fails with 403.
5. **Check:** onboard one phone in Hindi and one in English.

## What Phase 3 built (voice to profile, FR-2 to FR-5)

### Decisions that deviate from PRD.md (made with the user, 2026-10-13)

- **STT is IBM Watson only.** Its Indian models are `hi-IN_Telephony` and `en-IN_Telephony`, so **voice notes work in Hindi and English only** ([IBM next-gen models](https://cloud.ibm.com/docs/speech-to-text?topic=speech-to-text-models-ng)).
  - **Other languages:** workers who chose one of the other 11 are told voice isn't available and asked to type. FR-2 accepts text.
  - **Whisper:** the PRD's Whisper provider wasn't built (the user declined it); `SpeechToText` is the seam for adding it.
- **LLM defaults to OpenAI** (no watsonx credits yet).
  - **API and model:** it uses the Responses API with a strict JSON schema, model `gpt-6-luna` (`OPENAI_MODEL`).
  - **Granite:** a provider for Granite on watsonx.ai (`ibm/granite-4-h-small`, IAM token cached) is built; select it with `LLM_PROVIDER=watsonx`. IBM's public docs don't show the chat request body, so it follows the OpenAI-compatible shape the SDKs use. **Verify it with the smoke suite once credits exist.**
- **Numbered replies again** (sandbox limitation): "1 = Correct, 2 = Change", with yes/no words accepted.
- **`voice_notes.media_url` is nullable** (migration `0002`). Typed descriptions and follow-up answers are stored as transcripts too, so "combined transcript" (FR-5) covers every input.
- **Conversation context is encoded in `workers.state`**, e.g. `follow_up:location:2` (field asked, follow-ups so far). No schema change was needed.
- **Location is not geocoded yet:** city, area and pin code are stored as text with `lat`/`lng` null. Geocoding comes with distance matching in Phase 5.
- **Audio is never stored by us:** we keep the Twilio media URL and the transcript. Twilio still holds the media; deleting it after 30 days (PRD) is a Phase 7 retention job.

### Pipeline (all in the Celery worker)

1. **Download:** `TwilioProvider.fetch_media` downloads the voice note with account auth. It only accepts `api.twilio.com` URLs (blocking server-side request forgery), caps size at `MEDIA_MAX_BYTES`, and retries 3 times.
2. **Acknowledge:** the worker is sent "listening…" right away.
3. **Convert:** `app/ai/stt.transcode_to_wav` converts any audio to 16 kHz mono WAV with ffmpeg (stdin to stdout, no temp files). Notes over `VOICE_MAX_SECONDS` (120) are rejected.
4. **Transcribe:** `WatsonSTT` transcribes (3 attempts on transient errors), and the transcript is saved to `voice_notes`.
5. **Extract:** `app/services/profile.extract_profile`:
   - **Redact:** `app/ai/redact` strips phone, Aadhaar, PAN, voter-ID, passport and other 9+ digit numbers (any script's digits), keeping pin codes and pay.
   - **Call the LLM:** with the combined transcript (newest 10 inputs), the previous profile and the field the latest message answers.
   - **Validate and retry:** the output is validated with Pydantic. **On invalid output it retries once with the validation error**, then returns None, which falls back to a follow-up question (FR-3).
   - **No invented skills:** the LLM must quote verbatim `evidence` for every skill, and skills whose quote isn't in the transcript are dropped in code. Evidence is stripped before storing.
6. **Next step:**
   - **Follow-ups (FR-4):** missing trade, experience or location get one follow-up question at a time, at most `MAX_FOLLOW_UPS` (3) per round.
   - **Summary (FR-5):** otherwise the worker gets the summary (under 300 characters, translated labels and trade names), with 1 = Correct or 2 = Change.
   - **Change** re-extracts on the combined transcript.
   - **Correct** sets `worker_profiles.confirmed`.
7. **Logging (PRD guardrail):** every LLM call logs provider, model, prompt ID and hash, character counts, tokens, latency and outcome. It **never logs the prompt or response text**, because they contain personal data.

### Settings and readiness

- **New settings:** `STT_*`/`WATSON_*`, `LLM_*`, `OPENAI_*`, `WATSONX_*`, `IBM_IAM_URL` and `MAX_FOLLOW_UPS`, all in `.env.example`. Production refuses to start without the selected provider's keys.
- **`/readyz`:** adds `stt` and `llm` checks when they're configured. These call a free authenticated endpoint (model list or IAM token), cached for 60 seconds while passing.

### AI evaluation set (the Phase 3 done-when)

- **Data:** `seed/eval/profiles.jsonl` holds 30 synthetic cases: 10 Hindi (Devanagari and Hinglish), 10 Indian English, and 2 each in Bengali, Marathi, Tamil, Telugu and Gujarati. They cover all 8 trades and many cities.
- **Run it:** `docker compose exec worker python -m app.ai.evaluation`, or from `apps/api` with `OPENAI_API_KEY` set. It prints per-case and per-language accuracy and exits non-zero if any of trade, skills or location is below 85% (`--min`). `--json report.json` saves details.
- **Scoring:** documented in `app/ai/evaluation.py`. Predicted skills that match nothing expected are listed for human review.
- **Unverified:** the cases and expected answers were written by Claude Code and need a team review. The run itself has **not** happened yet.

## How to run

### Full stack (needs Docker)

```bash
cp .env.example .env    # set POSTGRES_PASSWORD; DATABASE_URL must use the same credentials
docker compose up --build    # migrate runs first, then api + worker
curl localhost:8000/healthz
curl localhost:8000/readyz   # 200 with database/pgvector/redis = ok
```

### Backend checks without Docker

```bash
cd apps/api
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements-dev.lock
.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/mypy app tests
.venv/bin/pytest --cov --cov-fail-under=80
```

Tests marked `db` (migration up and down, model and migration drift, constraints, cascades, `/readyz` against real services) need a real Postgres with pgvector and Redis. Without them those tests **skip**. To run them, point at real services:

```bash
TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/kaamsetu_test \
TEST_REDIS_URL=redis://localhost:6379/0 \
REQUIRE_DB_TESTS=1 .venv/bin/pytest
```

`REQUIRE_DB_TESTS=1` (set in CI) turns those skips into failures. **The `db` tests drop and recreate the schema**, so never point them at a real database.

### Regenerating lock files (after editing dependencies in pyproject.toml)

Generate them with uv on Python 3.12 (about 30 s). The dev lock is constrained to the runtime lock, so tests run on exactly the versions the image ships:

```bash
cd apps/api
docker run --rm -v "$PWD:/src" -w /src --user "$(id -u):$(id -g)" -e HOME=/tmp python:3.12-slim sh -c '
  pip install -q --user uv==0.8.17 && export PATH=/tmp/.local/bin:$PATH &&
  uv pip compile -q --python-version 3.12 --generate-hashes pyproject.toml -o requirements.lock &&
  uv pip compile -q --python-version 3.12 --generate-hashes --extra dev --constraint requirements.lock pyproject.toml -o requirements-dev.lock'
```

### Migrations

```bash
cd apps/api
alembic upgrade head            # uses DATABASE_URL
alembic upgrade head --sql      # print SQL without a database
```

`EMBEDDING_DIM` is baked in by `0001_initial`. Changing it after the first migration needs a new migration.

### Running the full suite inside the image (as done for Phase 1 sign-off)

```bash
set -a; . ./.env; set +a
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "CREATE DATABASE kaamsetu_test"  # once
docker run --rm --network kaamsetu_default --user root -v "$PWD/apps/api:/src:ro" \
  -e TEST_DATABASE_URL="postgresql+psycopg://$POSTGRES_USER:$POSTGRES_PASSWORD@postgres:5432/kaamsetu_test" \
  -e TEST_REDIS_URL=redis://redis:6379/1 -e REQUIRE_DB_TESTS=1 \
  kaamsetu-api:local sh -c 'cp -r /src /tmp/api && cd /tmp/api && pip install -q ".[dev]" && pytest --cov --cov-fail-under=80'
```

## Conventions

- Name tests and commits after their requirement ID (`FR-x`). Foundation work with no FR uses `P1`.
- Put every external service behind an interface with a mock for tests. Mark real-service smoke tests separately.
- Keep worker-facing text in `app/i18n` and never inline it.
- Secrets live only in the environment. Add every new setting to `.env.example`.
- Starlette warns that `httpx` in TestClient is deprecated (it prefers `httpx2`). The PRD mandates httpx, so the warning is filtered in `pyproject.toml`.
